# Rule data

Runtime rule data is static JavaScript under `src/rule-data/`:

- `language.js`: `ALLOWED_WORDS`, `RULE_WORDS`, semantic roles and shared vocabulary
- `exact.js`: phrase-specific rules
- `grammar.js`: productive expressions, role frames and broad fallbacks
- `../rules-data.js`: candidate-scoring parameters and public-data assembly

`ALLOWED_WORDS` is every word accepted from censored captions and Whisper; keep its order stable
(Whisper uses it for tie-breaks). Add a word only when real censored automatic tracks never show
it visible and manual-auto evidence repeatedly shows it whole (`chicken [__]` does not validate
`chickenshit`). `RULE_WORDS` is the subset rules may output; add a word only with a validated rule.
`NOT_CENSORED_WORDS` lists visible words to skip when inferring a hidden word; keep it disjoint
from `ALLOWED_WORDS`.

In Whisper modes a rule fill is provisional: it stays when Whisper abstains but never replaces a
word Whisper heard. Reintroduce rule overrides only with creator-diverse audio labels.

A literal `[__]` in a template (`a [fucking] [__].`) matches one blank and leaves it open for Whisper;
single-blank rules never fill a blank next to another blank, and wildcards never match a blank.

`<wc-name>` in a template matches one word from `WORD_CLASSES["wc-name"]` (`language.js`). The
`fallback/word-class` group and the class lists were generated by `tools/mine-word-class-rules.js`.
Release 1.6.3 disables the generated word-class group and retains the diagnostic miner.
The miner cannot write runtime rules. Keep its reports separate from rule admission evidence.

Groups have explicit priorities; compiled priority comes from group, authored position and
expansion, so source groups can be reordered without changing behavior.

## Admission gates

First-choice precision with at least 2 named creators: one-answer literals 90% at 4–5 matches
or 85% at 6+; generalized and word-class rules 92% at 5+; two-, three- and four-plus-candidate rules 92% at 6+,
95% at 10+ and 97% at 20+.

Measure synthetic and manual-auto evidence separately. Synthetic is the primary tier: a rule that
passes on synthetic is admitted even if manual-auto falls below the gate (record the manual-auto
numbers). A rule passing only on manual-auto must not fall below its gate on synthetic wherever
synthetic has enough matches to apply it.
### Word-class diagnostics (not runtime admission)

The word-class miner filters to eligible synthetic/manual-auto rows with known creators **before
tokenization or vocabulary construction**. `pairClass`, when present, is authoritative; a
conflicting `tier` or unsupported provenance is rejected, while either canonical-only
`pairClass` or legacy `tier` rows are supported. Explicit `labeled` must be `true` and explicit
`label` must be `eligible`; absent flags retain legacy expected-array compatibility. Expected
labels must be nonempty string arrays resolving to one distinct single word (an internal
apostrophe is supported). Lowercase, trim and terminal punctuation removal match the benchmark's
basic comparison; masked words, multiword labels and ambiguous alternatives are rejected, with
no spelling, slang or context-dependent aliases. Excluded labels cannot contribute vocabulary or
score denominators. Direct `creatorGate` additionally fails closed on invalid creator/provenance
among remaining labeled inputs; preparation, mining, vocabulary and compiled review filter them.
Valid canonical YouTube channel IDs take precedence
over aliases; fallback names are Unicode-normalized, case/whitespace-normalized and reject
placeholders such as unknown, N/A and anonymous. Two folds use the low bit of the first SHA-256
byte of `word-class-creator-v1\0` plus the canonical creator key (`id:` or `name:`). Assignment is
dataset-independent and groups the whole creator across tiers; adding secondary-only creators
cannot move existing creators. This new hash gate invalidates prior sorted/alternating-fold audit
results. Existing audit artifacts describe the old gate; reports must be rerun, not relabeled.

In each direction, training alone must choose and support the same word/tier; validation
first-choice matches and marginal runtime blanks each need 92% at 5+ matches from 2+ correct
creators. Training marginal support must also pass. Manual-auto additionally needs a 95% Wilson
lower bound of 0.80; synthetic reversal blocks manual fallback on full data and within each
train/validation subset when synthetic has 5+ matches. Insufficient fold support rejects the
pattern. Greedy selection prioritizes synthetic-passing candidates ahead of manual-only
candidates, rechecks remaining marginal blanks and scores only the passing tier. Basic template
emission eligibility (output word, literals, available classes, existing templates) is checked
before selection, so discarded templates do not consume coverage.

The reusable `validateCompiledCandidate(candidate, rows, options)` helper additionally checks a
single chosen candidate in isolated compiled VMs, using only TRAIN `rows.tokens` for each fold's
static vocabulary. Archive `tokenIndex` is retained only as ID metadata, never used as a local
slot. A single-blank context always targets local slot 0, even if its original `slotIndex` is
larger. Multiple blanks require an explicit local `targetSlotIndex`, or a valid `slotIndex` with
`contextFaithful: true`; otherwise the row is rejected. `prepareRows` preserves the original
metadata and records `targetSlotIndex`, targeting that blank for tokenization as well. The helper
counts actual trace alternatives at this local target, including blocked matches, not contextual
POS membership; baseline occupancy uses the same local slot and spanning decisions. Returned
`excluded` counts distinguish unsupported/ineligible labels, ineligible evidence and ambiguous
targets. Baseline-current-empty marginal
support is checked separately. Both training and validation all-match/marginal gates must pass,
with training labels independently choosing the same word/tier. Missing emitted vocabulary or
sparse compiled coverage rejects; results retain separate per-fold/tier supports. This is a
**retrospective diagnostic**, not admission or a prospective accuracy claim: selection uses the
same data, and pooled/effective coverage, multi-slot behavior and independent/frozen vocabulary
remain unresolved. It does not deploy rules, write source/cache, or change default mining.

**Unresolved safety gate:** default miner counts are tokenizer-pattern matches, not matches of the final compiled
static-class templates. Vocabulary learned from the same dataset is neither independent nor
frozen; it can change compiled match coverage and leak across folds. Final compiled-template
first-choice and marginal validation with independent/frozen vocabulary is required before
runtime admission. Do not infer runtime accuracy from these diagnostic counts.

`--write` always fails explicitly, before any archive loading. `--report`, `--audit` and
`--dry-run` remain diagnostic-only; reports say **not runtime admission**. `--report` accepts only
new files under the real project `tmp/`, with existing non-symlink parents, no symlink path
components, and exclusive creation (existing outputs cannot be overwritten). `--audit` audits
mined candidates, not committed templates; baseline loading removes generated blocks only in an
isolated VM. Focused regressions run without acquisition or browser access:
`node --expose-gc --max-old-space-size=128 tests/mine-word-class-rules.test.js`.

Filmot snippets never justify a rule alone. Prefer narrow phrases over frames, and prefer retiring
a below-gate rule over keeping its coverage. Add positive, near-miss, ambiguity, punctuation and
priority tests with every change.

Evidence records live in `corpus/rules/evidence.jsonl`, not in runtime files.
`tests/rules-data-structure.test.js` hashes the compiled rule data; change the hash only after an
intentional rule change and `npm test -- --benchmark`.
